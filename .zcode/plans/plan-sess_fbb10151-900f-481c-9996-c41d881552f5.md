# Phase 4 — AI Agent 实施计划（基于 CloudWeGo eino）

## 决策（用户已确认）
1. **框架**：CloudWeGo eino（`github.com/cloudwego/eino` + `eino-ext`），ReAct Agent 内部处理工具循环
2. **LLM Provider**：OpenAI 兼容 API（`eino-ext/components/model/openai`），用户填 BaseURL + API Key + Model
3. **API Key 存储**：存 OS 密码库（复用 Phase 5 SecretStore），BaseURL/Model 存 SQLite
4. **目标 Host**：Agent 关联终端会话——每个会话有自己的 Agent，ssh_exec 等工具自动作用于该会话的 Host
5. **流式输出**：LLM 回复流式传输到前端（打字机效果）
6. **范围**：全部 7 个 Tool + 完整 Permission 系统 + 诊断场景

## 技术依据（已通过源码研究确认）
- eino ReAct Agent（`flow/agent/react.NewAgent`）：**内部自动**处理 LLM→tool call→execute→feed back→repeat 循环，`MaxStep` 控制上限
- 工具定义：`components/tool/utils.InferTool[T,D]`（从 Go struct 推断 JSON schema）
- 流式：`agent.Stream(ctx, msgs)` → `StreamReader[*schema.Message]` → 逐块 `Recv()` 拿增量文本
- 模型：`eino-ext/components/model/openai.NewChatModel`，`ChatModelConfig{BaseURL, APIKey, Model}`

## 架构

```
前端 AgentView（对话 UI）
  ↓ OpenChat / SendMessage（Wails 绑定）
AgentService（interfaces）
  ↓
AgentRuntime（application）—— 管理每会话 Agent 实例 + 流式事件
  ↓ 构造
eino ReAct Agent（ToolCallingModel + Tools）
  ↓ 调用工具时
ToolExecutor（infrastructure/agent/tools）—— 7 个工具实现
  ↓ ssh_exec 复用
ssh.Manager.ExecInSession(sessionID, cmd)
  ↓ ssh_read_file / ssh_write_file
sftp.Manager（Phase 3）
```

## 执行步骤

### Step 1 — 后端：LLM 配置 + eino 依赖
- `go get github.com/cloudwego/eino github.com/cloudwego/eino-ext`
- `domain/config.go`：AppConfig 加 `LLMConfig{BaseURL, Model}`（API Key 不在此，走 SecretStore）
- `application/secret_service.go`：加 `SaveLLMKey/GetLLMKey/DeleteLLMKey`（key=`airemote:llm:apikey`）
- `application/llm_service.go`：`LLMService` 管理配置读写 + 用 SecretStore 存取 API Key

### Step 2 — 后端：7 个 Tool 实现（infrastructure/agent/tools）
用 eino 的 `utils.InferTool` 定义，每个工具接收 sessionID（运行时注入）+ 参数：
- `local_exec`（cmd）→ `os/exec` 本地执行，READ 权限
- `local_read_file`（path）→ `os.ReadFile`，READ
- `ssh_exec`（cmd）→ `ssh.Manager.ExecInSession(sessionID, cmd)`，READ
- `ssh_read_file`（path）→ `sftp.Manager` 读远程文件，READ
- `ssh_write_file`（path, content）→ `sftp.Manager` 写远程文件，WRITE
- `upload`（localPath, remotePath）→ 读本地 + SFTP 写，WRITE
- `download`（remotePath, localPath）→ SFTP 读 + 写本地，READ

`ssh.Manager` 加 `ExecInSession(sessionID, cmd) (string, error)`：从 sessionID 拿底层 `*ssh.Client`，开新 session 执行 `CombinedOutput`。

### Step 3 — 后端：Permission 系统集成
- eino ReAct Agent 的工具执行不经过我们的 Permission 门禁——需要在工具的 `InvokeFunc` 里插入**前置检查回调**。
- 设计：`ToolExecutor` 持有 `PermissionGate` 回调。每个工具执行前调 `gate.Check(toolName, permission, args)`：
  - READ → 自动放行
  - WRITE/DANGEROUS → gate 返回 `ErrApprovalRequired`，AgentService 通过事件通知前端，等待用户批准/拒绝
- 因 eino Agent 的工具调用是同步的，WRITE/DANGEROUS 用**同步阻塞**等待前端批准（Go channel）。

### Step 4 — 后端：AgentRuntime（application）
- `application/agent_runtime.go`：
  - `Runtime` 管理按 sessionID 的 Agent 实例（lazily 创建）
  - `StartChat(sessionID, message)`：构造 eino Agent（model + 7 tools + permission gate），调 `agent.Stream`，逐块读 StreamReader，通过 `SessionEvents` 发 `agent:<id>:chunk` / `agent:<id>:toolcall` / `agent:<id>:done` 事件
  - `Cancel(sessionID)`：取消进行中的 Stream（context.CancelFunc）
  - `Stop(sessionID)`：清理 Agent 实例

### Step 5 — 后端：Wails AgentService（interfaces）+ main.go
- `AgentService`：`ConfigureLLM(baseURL, model, apiKey)` / `GetLLMConfig` / `StartChat(sessionID, message)` / `CancelChat(sessionID)` / `ApproveToolCall(reqID, approved)`
- 事件名：`agent:<sessionID>:chunk`（流式文本）/ `:toolcall`（工具调用通知）/ `:approval`（需批准）/ `:done` / `:error`
- `main.go`：组装 LLMService + ToolExecutor + AgentRuntime + 注册 AgentService

### Step 6 — 前端：Agent UI（features/agent）
- `api.ts`：AgentService 绑定封装
- `store.ts`：每会话的消息历史 + pending approvals
- `AgentView.tsx`：
  - 顶部：LLM 配置入口（BaseURL/Model/API Key，API Key 密码框）
  - 对话区：消息气泡（user/assistant）+ 流式打字效果
  - 工具调用卡片：内联显示 `ssh_exec: uptime` + 结果（可折叠）
  - 批准弹窗：WRITE/DANGEROUS 操作弹出确认框
  - 输入框 + 发送/取消按钮
  - 关联当前终端会话（从 terminal store 的 activeId）

### Step 7 — 终端会话与 Agent 关联
- 终端 tab 旁边加"Agent"按钮，点击切换到 Agent 视图，自动绑定当前会话
- AgentView 根据 activeSessionId 加载该会话的消息历史

### Step 8 — 验证 + 文档
- 构建通过；配置 LLM（OpenAI/兼容 API）；开终端会话；在 Agent 里问"检查这台机器的 CPU 和内存"，验证 ssh_exec 工具调用

## 风险与缓解
- **eino 依赖体积**：eino + eino-ext 会增加 binary 体积（预计 +5-10MB）。可接受（仍单 Binary）。
- **流式 + 工具批准的交互复杂度**：WRITE/DANGEROUS 工具需同步等待用户批准。用 Go channel 实现阻塞等待，前端通过事件 + 绑定方法完成批准/拒绝。
- **eino API 变动**：eino 相对年轻，API 可能变。锁定具体版本（非 @latest）。
- **API Key 安全**：API Key 经 SecretStore 存 OS vault，不落 SQLite，与 Phase 5 一致。
