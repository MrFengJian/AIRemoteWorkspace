## 批次 P0：错误反馈与文案（用户感知最强）

### 1. 新建全局消息提示（toast）系统
仿照现有 confirm 弹窗的架构（zustand store + AppShell 唯一挂载点）：
- 新建 `frontend/src/stores/toast.store.ts`：消息队列、push/dismiss、自动消失（成功 3 秒 / 错误 5 秒）、最多同屏 4 条
- 新建 `frontend/src/components/ui/Toaster.tsx`：右下角堆叠（在状态栏上方），成功/错误/信息三种样式，全部使用现有设计变量（oklch token），带图标、关闭按钮和 aria 角色
- 新建 `frontend/src/lib/toast.ts`：`toast.success/error/info(msg)` 便捷函数
- `AppShell.tsx` 挂载 `<Toaster />`；更新 QueryProvider/ui.store 中 "future: global toasts" 注释

### 2. 补全约 10 处静默失败
- `src/lib/queryClient.ts`：加全局 MutationCache onError，所有 React Query mutation 失败统一 toast 兜底（主机增删改自动覆盖）
- `HostsView.tsx:89-92`：连接失败 → toast 错误原因（现在完全静默）
- `HostFormDialog.tsx` handleConnect 失败 → toast 具体原因
- `SettingsView.tsx:102-104`：设置保存失败 → toast（现在静默回滚，用户以为成功了）
- `ModelSettingsSection.tsx:77-109`：供应商启用/删除失败 → 迁移到 React Query（useQuery + useMutation + invalidate，queryKey `["model-providers"]`），失败自动获得兜底 toast，同时解决与 Agent 面板各自拉取的不一致
- `TerminalView.tsx`：分屏/重连/复制会话失败 → toast；`TerminalPanel.tsx` 剪贴板被拒 → toast 提示
- `terminal.store.ts` 的 "error" 状态接线：连接/重连失败时 `setSessionStatus(id,"error")`（红色状态点样式已存在，从未被调用）
- `AgentView.tsx:353`：消息 `key={i}` → 消息加自增 id

## 批次 P2：SFTP 体验

- **修复 store 冲突 bug**：独立文件页与终端内嵌面板共用全局 `useSftpStore`，打开内嵌面板会把独立页正在浏览的目录重置 → 状态改为组件内部（自定义 hook），两实例天然隔离
- `SftpView.tsx:228` 原生 `<select>` 换成共享 Select 组件，修复错乱缩进
- **上传/下载进度**：
  - 后端 `internal/application/sftp_service.go`：Download/Upload 改分块循环，每块发进度事件（复用终端输出的 Go→JS 事件模式，事件 `sftp:transfer:{id}`，载荷含 transferred/total）
  - 前端 `sftp/api.ts` 订阅进度；SftpView 状态条显示进度条；传输中禁用上传/新建/刷新按钮；完成/失败 toast
- 删除/重命名/新建文件夹失败 → toast（现在只有列表错误有横幅）
