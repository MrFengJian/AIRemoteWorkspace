# 快捷键系统实现计划（仿 Xshell）

## 现状与目标

当前应用**没有任何快捷键体系**：所有终端操作（复制/粘贴/查找/分屏/关标签）100% 依赖右键菜单，无 Ctrl/Cmd 系快捷键。本计划引入 Xshell 风格的快捷键系统：

1. 为高频操作提供默认快捷键，覆盖终端、标签页、分屏、视图、应用五个分类
2. 设置页新增「快捷键」分类：可视化列表 + 按键录制 + 冲突检测 + 恢复默认（Xshell 的 Keyboard 设置页样式）
3. 持久化到后端 `AppConfig`（SQLite），复用现有设置的乐观更新链路

## 一、命令清单与默认键位

只存**用户覆盖项**（非默认值），键位字符串统一格式 `Ctrl+Shift+C`（修饰键固定顺序 Ctrl/Alt/Shift/Meta，键名大小写不敏感）。次要命令默认不绑定（Xshell 同款做法），用户可在设置中自行分配。

| 分类 | 命令 | 默认键 |
|---|---|---|
| 终端 | 复制 / 粘贴 / 全选 / 查找 | Ctrl+Shift+C / Ctrl+Shift+V / Ctrl+Shift+A / Ctrl+Shift+F |
| 终端 | 清屏 / 放大 / 缩小 / 重置缩放 | 无 / Ctrl+= / Ctrl+- / Ctrl+0 |
| 标签页 | 新建本地终端 / 关闭标签 | Ctrl+Shift+T / Ctrl+Shift+W |
| 标签页 | 下一标签 / 上一标签 | Ctrl+Tab / Ctrl+Shift+Tab（若 WebView2 吞掉则改 Ctrl+PgDn/PgUp） |
| 标签页 | 切换到标签 1-9 | Ctrl+1..9（Ctrl+9 = 最后一个标签，浏览器惯例） |
| 标签页 | 复制标签 / 重连 | 无（可自定义） |
| 分屏 | 水平/垂直分屏 / 关闭分屏 / 切换分屏焦点 | 无（可自定义，当前最多 2 分屏） |
| 视图 | 切换 SFTP / Agent / 主机侧栏 | 无（可自定义） |
| 应用 | 打开设置 | Ctrl+, |

## 二、核心架构：window 捕获阶段分发（新建 `frontend/src/keybindings/`）

**关键机制**：在 AppShell 挂一个 `window.addEventListener("keydown", handler, { capture: true })`。捕获阶段先于 xterm 的 textarea 监听器触发，命中快捷键时 `preventDefault() + stopPropagation()`，按键就不会流入 PTY——一套机制同时覆盖 UI 焦点和终端焦点两种场景，无需 `attachCustomKeyEventHandler`。

新文件：
- `commands.ts` — 命令定义表（id、i18n key、分类、默认键）
- `match.ts` — 键位字符串解析 / KeyboardEvent 归一化 / 匹配 / 显示格式化（处理 `=` `-` `PgDn` 等；IME 组合态 `isComposing` 直接跳过）
- `store.ts` — zustand：`overrides` + `resolvedBindings()`（默认+覆盖合并）、`setOverride/clearOverride/resetAll/load`
- `registry.ts` — 命令处理器注册表（commandId → handler）+ pane 动作 API 注册表（paneId → {copy, paste, selectAll, find, clear, zoom…}，TerminalPanel 挂载时注册）
- `useShortcutDispatcher.ts` — 上述 window 捕获监听 + 分发逻辑

**目标 pane 路由**：`terminal.store.ts` 新增 `activePaneId`（TerminalPanel 在 xterm textarea focus 时上报）。分发终端类命令时：目标 = activePaneId（若属于当前活动标签）否则活动标签的 paneIds[0]，再调其注册的 API——复制/粘贴等已有实现（TerminalPanel 的 handleCopy/handlePaste）直接复用。分屏切换焦点 = 在活动标签的两个 pane 间 toggle。

**处理器接线**：
- `TerminalView.tsx`（常驻挂载）：注册标签页命令（next/prev/close/goto-N/new/duplicate/reconnect）、分屏命令、视图命令（toggleSftp/toggleAgent/toggleSidebar）、终端命令的 pane 路由入口
- `AppShell.tsx`：注册 `app.settings`；启动时 `GetAppConfig` 初始化快捷键 store；挂 dispatcher

**缩放实现**：TerminalPanel 加 `zoomDelta` 本地 state，`term.options.fontSize` 热更新 + refit（会话生命周期内有效，不持久化，同 liveThemeId 模式）。

## 三、设置 UI（Xshell 风格快捷键编辑页）

- `ui.store.ts`：`SettingsCategory` 增加 `"shortcuts"`（插在 models 与 advanced 之间）
- 新建 `features/settings/ShortcutSettingsSection.tsx`：
  - 按分类分组的行列表：命令名 | 键位按钮 | 覆盖指示（非默认时显示恢复按钮）
  - **录制交互**：点击按钮进入监听态（提示"按下新组合"），按下任意非纯修饰键即录制；Escape 取消、Backspace 清除绑定；录制监听用捕获+stopPropagation，避免触发全局分发
  - **合法性校验**：可打印单键（字母/数字/Enter/空格）不允许无 Ctrl/Alt/Meta 修饰（避免误触）；F 键、Insert 等导航键可裸绑（支持 Xshell 的 Shift+Insert 风格）
  - **冲突检测**：与其他命令已解析键位相同时，红字提示冲突命令名并阻止保存
  - 顶部「全部恢复默认」按钮；每次修改即时走现有 `updateConfig({ shortcuts })` 乐观更新持久化
- 菜单提示：`MenuItem` 增加 `shortcut?: string`，右键菜单右侧渲染 `<kbd>` 样式提示（TerminalPanel/TerminalView 的菜单项从 resolved bindings 取值）——Xshell 菜单同款观感

## 四、后端改动

- `internal/domain/config.go`：`AppConfig` 增加 `Shortcuts map[string]string \`json:"shortcuts,omitempty"\``（仅覆盖项；`DefaultConfig()` 保持 nil = 全默认，旧库无需迁移）
- `internal/application/config_service.go`：无需兜底逻辑（nil 即默认）
- 重新生成 Wails TS 绑定：`wails3 task generate:bindings`

## 五、i18n

`locales/zh.ts` / `en.ts` 新增：设置分类名、33 个命令标签、分类标题、录制/冲突/恢复提示文案。

## 六、实施顺序

1. 后端 `AppConfig.Shortcuts` 字段 + 重新生成绑定
2. `keybindings/` 核心模块（commands/match/store/registry/dispatcher）+ AppShell 接线与初始化
3. `terminal.store` activePaneId；TerminalPanel 注册 pane API、焦点上报、缩放；TerminalView 注册全部命令处理器
4. 右键菜单快捷键提示（MenuItem.shortcut + Kbd 渲染）
5. 设置页「快捷键」分类 + 录制/校验/冲突检测 UI
6. i18n 文案
7. 验证：`npx tsc --noEmit`、前端构建、`wails3 task build`；手动清单——终端内复制/粘贴/查找不漏字到 PTY、标签切换/关闭、Ctrl+数字、设置录制与冲突提示、重启后自定义键位保留

## 风险与对策

- **WebView2 加速键拦截**：Ctrl+Tab、Ctrl+=/-/0 可能被 WebView2 浏览器层吞掉不到达页面 → 实现时第一时间验证；若被吞，改默认键位为 Ctrl+PgDn/PgUp、Ctrl+Shift+= 等（设置页本身就能改键，用户可自行调整）
- **输入框中触发**：Ctrl+Shift+X 系组合在 Agent 输入框等处仍会触发终端命令（路由到最近聚焦的 pane）——与 Xshell 全局行为一致，可接受
