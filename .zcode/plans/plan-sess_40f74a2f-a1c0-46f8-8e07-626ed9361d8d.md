# K8s 面板（Phase 7 延后项落地）—— kubectl CLI 同构方案

## 目标与范围（按你的约束）

完全复制 Docker 面板的架构（kubectl 驱动，SSH exec 通道 / 本地 argv 双通道，零 SDK 依赖），支持**常规资源查看与管理 + Pod 日志 + 工作负载启停**；**不做** CRD / Operator 这类灵活性过强的资源（自定义资源不出现在面板中）。

**6 个子标签**（与 Docker 面板同构）：
| 标签 | 内容 | 管理操作 |
|---|---|---|
| 概览 | server/client 版本、当前 context、节点列表（状态/角色/版本/IP，只读）、Pod 按状态汇总、工作负载计数 | 无 |
| 工作负载 | **Deployments / StatefulSets / DaemonSets**（kind 徽章、副本/就绪/镜像/年龄） | Deployment/StatefulSet：**停止(scale→0)/启动(scale 恢复)/重启/设置副本数**；DaemonSet：**重启(rollout restart)**（无 scale 语义，UI 按类型显示可用动作） |
| Pods | 名称/状态/重启次数/节点/IP/容器清单 | **删除重建（delete pod，确认后执行）**、跳转日志 |
| Services | 类型/ClusterIP/端口/选择器（只读） | 无（右键插入 describe 命令） |
| 事件 | Warning 优先，按时间倒序（只读，截取最近 200 条） | 无 |
| 日志 | Pod 选择器 + **多容器二级容器选择器** + tail 档位（100/200/500/1000），一次性拉取；跟随走"插入终端 `kubectl logs -f`" | 无 |

集群访问 = 主机上已配置好的 kubectl + kubeconfig（与 Docker 面板信任模型一致）；kubectl 未安装 / 集群不可达分别降级为平静提示（复用 ErrorHint 三级模式）。

## 一、后端（Go）

### 1. `internal/domain/kubernetes.go`（新增）
```go
K8sClusterInfo{ClientVersion, ServerVersion, Context, NodesReady, NodesTotal, PodsRunning/Pending/Succeeded/Failed/Unknown, WorkloadCount{Deployments, StatefulSets, DaemonSets}}
K8sNode{Name, Status("Ready"/...), Roles, Version, InternalIP, Age}
K8sWorkload{Kind("Deployment"/"StatefulSet"/"DaemonSet"), Namespace, Name, Replicas, Ready, Updated, Available, Age, Images[]string}
K8sPod{Namespace, Name, Status(Phase+waiting reason), Ready, Restarts, Age, Node, IP, Containers[]string}
K8sServiceInfo{Namespace, Name, Type, ClusterIP, ExternalIP, Ports, Age, Selector}
K8sEvent{Namespace, Type, Reason, Object, Message, Count, LastTimestamp, Age}
```

### 2. `internal/application/k8s_service.go`（新增，镜像 docker_service.go 结构）
- `runKubectl(ctx, sessionID, args...)`：本地 `runLocalArgs`（argv 直调）/ 远程 `shellQuote` 逐参数拼接走 `ExecInSessionCtx`——直接复用现有 `runLocalArgs`/`shellQuote`/`isLocalSessionID`
- **哨兵错误**：`ErrKubectlUnavailable`（CLI 缺失，复用 isDockerCLIMissing 同款识别逻辑换 kubectl 路径）、`ErrClusterUnreachable`（"connection to the server refused"/"unable to connect"/"no configuration has been provided" 等）
- **kubectl 标识符校验**（安全细节）：namespace/name/container 过 DNS-1123 模式校验，kind/action 走封闭白名单——防 shellQuote 挡不住的"flag 注入"（参数以 `--` 开头会被 kubectl 当 flag）
- 方法清单（全部 `-o json` 输出，解析走 k8s_parse）：
  - `GetClusterInfo`：version -o json（致命）+ get nodes -o json + get pods -A 自定义列（best-effort 降级）
  - `ListNamespaces`、`ListNodes`、`ListWorkloads(kind∈{deployments,statefulsets,daemonsets} 白名单, namespace|"")`、`ListPods`、`ListServices`、`ListEvents`（--sort-by 排序 + 截 200 条）
  - `GetPodLogs(sessionID, ns, pod, container, tail)`：`kubectl logs <pod> -n <ns> [-c <c>] --tail N --timestamps`，tail 10~1000 钳制 + 256KiB 封顶（复用 capString）
  - `WorkloadAction(sessionID, kind∈{deployment,statefulset,daemonset}, ns, name, action∈{scale,restart} 白名单, replicas)`：scale 仅对 deployment/statefulset（`kubectl scale kind/name -n ns --replicas N`）；restart 三类均支持（`kubectl rollout restart kind name -n ns`）；kind×action 组合不合法直接报错
  - `DeletePod(sessionID, ns, name)`：`kubectl delete pod <name> -n <ns> --wait=false`（避免等待宽限期超时）
- namespace 为空时用 `--all-namespaces`

### 3. `internal/application/k8s_parse.go`（新增）
- 精简 struct 形状解析 kubectl JSON 文档（metadata/spec/status 标准对象，稳定）：restarts 求和、ready 容器计数、waiting.reason 提升为状态显示、DaemonSet 用 desiredNumberScheduled/numberReady、Age 由 creationTimestamp 人性化（Xd/Xh/Xm，Go 侧计算）
- 单测 `k8s_parse_test.go`（fixtures：pods/deployments/statefulsets/daemonsets/services/events/version JSON、restarts 求和、age 格式化、标识符校验、kind×action 白名单、错误分类）

### 4. `internal/interfaces/k8s_service.go` + `main.go`
- 薄封装（统一 30s 超时，同 dockerTimeout 模式），直接返回 domain 类型
- main.go 构造 `application.NewK8sService(connManager)` + 注册 Wails 服务；`wails3 generate bindings -clean=true -ts` 重新生成

### 5. `tools/danger.go` 小补（Agent 通道对齐）
- `kubectl scale` / `kubectl rollout` → WRITE 级；`kubectl drain` / `kubectl taint` → DANGEROUS（delete 已是 DANGEROUS）——让 K8s 专家人设触发的这类操作正确进入审批

## 二、前端（React）

### 6. `frontend/src/features/k8s/`（新增，镜像 features/docker 两文件模式）
- `api.ts`：k8sApi 薄封装 + `k8sErrorKind()` 错误分类（notInstalled / clusterUnreachable / generic）
- `K8sView.tsx`：单文件子 Pane 拆分，6 个子 Tab；顶部**命名空间选择器**（"全部命名空间" + ListNamespaces 结果，组件态随会话保留）；queryKey 一律 `[资源, sessionID, ...]`、按 Tab `enabled` 懒加载、轮询共享 `monitorIntervalSeconds`、日志 pull-only
- 工作负载行带 kind 徽章；动作按类型渲染（scale 三按钮仅 Deployment/StatefulSet 显示，DaemonSet 只显示重启）；`useConfirm` 确认集合（停止/重启/删 Pod，删 Pod 用 danger 样式）；"启动"目标副本数取该负载最近非零副本数（本会话内记忆，无记录则 1）；"设置副本数"走 `askPrompt`；action mutation `onSettled` invalidate
- Pods/日志/右键菜单全部复刻 Docker 模式：状态圆点行块、行级 ContextMenu（复制名称/IP/镜像 + 插入 `kubectl logs -f / describe / exec -it -- sh` 到终端，只插不回车）、ErrorHint 三级降级

### 7. 集成点
- `TerminalView.tsx`：`rightTab` 联合类型加 `"k8s"`；工具栏 Ship 图标按钮（disabled=!activeSession）；icon tab 条 + 条件渲染 `<K8sView embeddedSessionID={activeSession.id} />`
- `keybindings/commands.ts`：`cmd("view", "view.toggleK8s", null)`（无默认键，与 toggleDocker 一致）+ TerminalView handler
- i18n：`k8s.*` 命名空间 zh/en 双语词条（约 70 键）
